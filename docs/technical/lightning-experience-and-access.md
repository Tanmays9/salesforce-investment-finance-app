# Lightning experience and access

The app uses native Salesforce navigation, object/record pages, Files, related lists, reports, dashboards and Screen Flows wherever possible. Custom LWCs are used for the research experiences and cross-record analysis that need coordinated data, filters or charts.

## App navigation

The `Investments` custom application is declared in `force-app/main/default/applications/Investments.app-meta.xml`. Its tabs include Overview, portfolios, holdings, mutual funds, SIP versions, plans, plan comparison, redemption review, watchlist, peer assignments, imports, data issues, Reports and Dashboards. The tab metadata and `NavItem` entries are generated by `tools/portfolio/pages.py` and the metadata generators.

## Component responsibilities

| Component | Placement | Responsibility and server contract |
|---|---|---|
| `invPortfolioResearch` | Overview app page | Calls `InvResearchService.getPortfolioResearch()` for the published run and `InvMovementService.compare()` for two dated runs. Offers summary, holdings filters, allocation/exposure, SIP and movement views. |
| `invFundResearch` | Reusable mutual-fund record page | Calls `InvResearchService.getFundResearch(fundId)` for fund identity, NAV/performance, peers, composition and the investor's position. Uses shared Chart.js static resource and standard table equivalents. |
| `invHoldingSummary` | Reusable holding record page | Shows account-level position, basis/coverage and redemption context; navigation links to the fund record for market research. |
| `invPlanComparison` | Plan comparison page | Calls `InvPlanScenarioService` for alternative generation/comparison and `InvResearchService` for baseline context. Mutations are permission-gated. |
| `invRedemptionReview` | Redemption review page | Calls `InvRedemptionService` for preview and saved lot/review evidence. It presents a review, not a trade action. |
| `invParseStatement` | CAS import Flow | Collects a transient optional PDF password and submits the staged import job. |
| `invWatchlistCard` | Overview page | Shows standard watchlist items with standard create/list navigation. A watchlist row is not a position. |

See `force-app/main/default/flexipages/Inv_Overview.flexipage-meta.xml`, `Inv_MutualFunds.flexipage-meta.xml`, `Inv_MutualFundRecord.flexipage-meta.xml`, `Inv_HoldingRecord.flexipage-meta.xml`, `Inv_PlanComparison.flexipage-meta.xml` and `Inv_RedemptionReview.flexipage-meta.xml` for the current page composition. `tools/portfolio/pages.py` preserves the generated page layout when regenerating metadata.

## Standard Flows and CRUD

`tools/portfolio/flows.py` generates Screen Flows for tracking a fund, creating/cloning/evaluating/approving plans, adding/editing/removing actions, setting targets/dependencies, mapping/confirming a CAS account, and submitting an import. These flows call Apex actions for domain behavior and use ordinary Salesforce records for navigation and review. Keep validations and financial calculations in Apex, not in Flow formulas or browser code.

Reports and dashboards live under `force-app/main/default/reports/Investments/` and `dashboards/Investments/`. `tools/portfolio/reporting.py` generates the standard report set and Portfolio Overview dashboard. Use standard Salesforce report charts for exportable, filterable aggregate reporting. The custom research components supply the interactive cross-filtering and coordinated chart/table experiences that standard dashboards cannot provide in the record context.

## Apex and data security

Read-only research methods use cacheable Apex facades and user-mode queries/access checks for records. Mutating plan, fund-tracking, import-mapping and account-confirmation operations check the `Inv_ManagePortfolio` custom permission and applicable record access. The parser callback has a separate `Inv_ParseStatements` permission and can stage import data only; it cannot confirm or post transactions.

Permission sets in source:

- `Inv_Viewer`: read-only access to investment records and research classes; assign for portfolio viewing.
- `Inv_PortfolioManager`: controlled edits to plans, watchlist/peer setup and reviewed import operations; assign together with `Inv_Viewer` only to intended portfolio operators.
- `Inv_Parser`: restricted API-only parser identity. Assign only to the integration user created for the parser; it is not a human user profile.
- `Inv_MigrationAdmin`: migration operations access. Assign only for a controlled migration window, then remove when not required.

Assignment is an org administration step; deploying the permission set does not assign it to users. Inspect the exact object, field and Apex class accesses in `force-app/main/default/permissionsets/` before a production assignment. Do not grant broad Modify All to make a failed workflow “work.”

## Client-side calculation rules

LWCs format INR as INR with two fractional digits and use appropriate precision for units/NAV. They may filter, sort, chart and collect user inputs, but must not derive authoritative account balances, FIFO lots, taxes, XIRR or plan readiness. Always use the returned coverage, dates and status when rendering a metric. A blank or incomplete server value must remain visibly unavailable rather than becoming zero.

## Page and component change process

When changing a page, update the generator and generated FlexiPage/manifest together. Preserve a single reusable fund record page with record context rather than creating one page per fund. Verify `recordId` behavior: the Overview page has no record ID and resolves the published portfolio; a fund/holding page receives the selected record's ID. Check layout, empty/loading/error states, keyboard access and table equivalents alongside chart changes.
